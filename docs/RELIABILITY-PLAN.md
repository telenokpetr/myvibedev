## 🚀 СМЕНА АРХИТЕКТУРЫ: браузерный бот (13 июля)

**Модерация чата переведена на Zoom WEB-клиент через Playwright (сервис
`bot-browser`, порт 9100) — и работает НАДЁЖНЕЕ desktop по всем статьям.**
Живой e2e 13.07: мат в чате → `deleted` с первого раза, серия удалений подряд,
**ни одного `flagged`, ни дребезга, ни диалога-подставы**. Причина: DOM вместо
OCR+пиксельных кликов. Вся возня desktop (красный/белый текст, закрывающаяся
панель, ховер-тулбар, диалог подтверждения) в web — просто DOM-вызовы.

Что доказано и почему web победил:
- Chromium headful под Xvfb, `navigator.webdriver=False` → Zoom не детектит бота.
- Чтение чата: `document.querySelectorAll('[class*="new-chat-message"]')` —
  автор+текст+id мгновенно и точно (OCR больше не нужен).
- Удаление: ховер → `button.new-chat-message__options-button` (последняя = «...»)
  → пункт «Удалить» → кнопка «Удалить» в диалоге — всё по DOM, успех
  проверяется исчезновением узла.
- Движок правил (profanity/spam) — общий, перенесён из desktop без изменений.
- Дедуп по DOM-id (не покадровый), бэклог первого чтения, кулдаун 90с — портированы.

Эксплуатация: митинг с залом ожидания → бота нужно впустить (Admit); для
удаления бот должен быть co-host/host. Оба ограничения те же, что и на desktop.

Осталось до полного сноса desktop: (1) музыка через тот же браузер (fake-mic +
PulseAudio + проверка, не режет ли Zoom web музыку без Original sound);
(2) запись; (3) снос desktop-воркеров и их OCR/GUI-кода.

  из чата — бот удалил его сам. Механика (всё выяснено живыми тестами):
  OCR-ридер отдаёт экранные координаты строки (ChatMessage.pos/pos_right;
  tesseract на TSV, склейка слов общая с paddle — app/ocrutil.py) → ховер по

  для мата/повторов (не для флуда).

## Решение по разрешению: Full HD

Возврат на **1920×1080** для качества записи (720p-запись мыльная). Память больше
не блокер: WSL-лимит поднят до 12 ГБ (`.wslconfig`), два 1080p Zoom-клиента ≈ 6 ГБ.
Плата — перекалибровка координат под 1080p; частично снимается фиксом №1 (отключить
экран preview, тогда автозаход почти не зависит от координат).

## P0. Автозаход по ссылке (главная надёжность)

**Симптом:** при входе через планировщик/веб бот застревал на экране пред-входа
(preview) и не входил; статус уходил в `error` (окно митинга не появилось).

**Причины:**
- `dismiss_startup_dialogs` не жал финальный «Join» на preview (частично уже
  исправлено: добавлены `join_meeting`/`click_prejoin_join`, но координата зависит
  от геометрии).
- Если Zoom уже запущен, повторный `zoom --url=zoommtg://` игнорируется — надо
  чистить старый процесс.
- Окно preview иногда выезжает за пределы экрана (см. P3).

**Решение:**
1. **Отключить экран preview глобально** — снять «Always show this preview when
   joining» (или через `zoomus.conf`: `showZoomWebinarUponEntry`/аналог). Тогда
   `zoommtg://` ведёт сразу в митинг/зал ожидания — клик Join не нужен, автозаход
   становится **резолюшн-независимым**. Это ключевой фикс.
2. В `zoom.launch` / `session._run_session` — **kill старого Zoom** перед запуском
   по ссылке (TERM→KILL→wait), чтобы `--url` гарантированно применился.
3. После входа программно вызвать `enable_original_sound()` (см. P2) и убедиться,
   что микрофон = BotMic и бот не замьючен.
4. Улучшить `wait_in_meeting`: помимо размера окна, проверять заголовок/наличие
   тулбара, различать «Waiting Room» (это не ошибка) и «Invalid meeting».

## P1. Original sound слетает при перезапуске Zoom

**Симптом:** после рестарта Zoom-клиента режим микрофона сбрасывается на «Noise
removal (default)», который **режет музыку** → музыки не слышно (подтверждено в
митинге 2).

**Причина:** режим не всегда персистится в профиле (особенно у гостя без аккаунта).

**Решение:** в автозаходе после входа всегда программно включать
`enable_original_sound()`. Проверять по баннеру/меню, что режим применился.

## P2. Модерация чата — чтение и действия

**Симптом:** движок правил (спам + мат RU/EN) работает и оттестирован, но бот
**не читает** реальные сообщения чата и **не применяет** действия.

**Причины:**
- `chatreader.py` — заглушки: `AtspiChatReader.poll()` и `OcrChatReader.poll()`
  возвращают `[]`.
- `gui.mute_participant` / `gui.delete_chat_message` — no-op (не откалибровано).

**Решение:**
1. **Чтение чата:** реализовать один из ридеров. OCR-путь надёжнее под Xvfb:
   открыть панель чата (хоткей), скринить область, tesseract-rus, дедуп новых строк.
   AT-SPI — если Zoom отдаёт дерево доступности (проверить `pyatspi`).
2. **Действия как хост:** откалибровать по скриншотам мьют участника и удаление
   сообщения (Participants → … → Mute; наведение на сообщение → Delete). Требует
   host-прав (бот уже умеет становиться хостом).
3. Включать модерацию в автозаходе, когда у события `moderate=True`.

## P3. Окно митинга больше экрана (тулбар за кадром)

**Симптом:** окно митинга 1188×800 при экране 1280×720 → нижний тулбар (Audio/
Mute/Leave) уходит за нижнюю кромку, клики по нему промахиваются; приходится
двигать окно вверх вручную.

**Причина:** Zoom открывает окно фиксированного размера больше рабочей области.

**Решение:** после входа приводить окно митинга к экрану — `wmctrl`
maximize (`add,maximized_vert,maximized_horz`) или `xdotool windowsize` под
геометрию экрана. На 1080p проблема меньше (800<1080), но привести всё равно.

## P4. Гость не подхватывает zoommtg при живом инстансе

**Симптом:** повторный `zoom --url=` при уже запущенном клиенте открывает домашний
экран, а не митинг (наблюдалось у воркера-2).

**Причина:** single-instance Zoom не всегда роутит новый URL в существующий процесс.

**Решение:** тот же kill-before-launch из P0.2 (единый механизм чистого входа).

## P5. Прочее (мелкое)

- **Cyrillic-имя через xdotool** ненадёжно — уже решено `paste_text` (xclip). Убедиться,
  что автозаход ставит имя через буфер, а не `type`.
- **Координаты облачной записи** (`rec_*`) выверялись под 1080p — при возврате на
  1080p снять пометку `_UNVERIFIED` после проверки.
- **Профиль Zoom в volume** — уже сделано; логин переживает пересоздание.
