# Zoom-бот: руководство оператора

Практическая инструкция по браузерному боту-модератору (`bot-browser`) и веб-панели.
Два бота работают параллельно (два мероприятия), каждый — под своим Zoom-аккаунтом.

## 1. Запуск и остановка

```bash
docker compose up -d          # поднять всё
docker compose ps             # статус контейнеров
docker compose restart bot-browser bot-browser-2   # перезапуск ботов
docker compose logs -f bot-browser                 # логи первого бота
```

Сервисы: `web` (панель), `bot-browser` (слот 0), `bot-browser-2` (слот 1), `db`, `redis`.

**Порты:**
- Веб-панель — http://localhost:8000
- Экран бота (noVNC): слот 0 — http://localhost:6080 , слот 1 — http://localhost:6081
- API ботов (обычно не нужно вручную): 9100 / 9101

## 2. Веб-панель

Открыть http://localhost:8000 . Сверху — вкладки **«Мероприятие 1 / 2»**: переключают,
каким ботом управляешь. Под названием — ссылка на текущий митинг слота.

Все блоки, кроме **«Живой просмотр»**, свёрнуты по умолчанию. Разворачивать —
кнопкой ▾ на блоке или «Развернуть всё» вверху.

## 3. Вход в Zoom-аккаунт бота (делается один раз, держится долго)

У каждого слота — свой аккаунт. Логинишься **руками** на экране бота (пароль вводишь
ты, сервер его не видит):

1. Вкладка нужного мероприятия → блок **«Аккаунт бота»** → **«1. Открыть форму входа»**.
2. **«2. Открыть экран бота»** (откроется noVNC того слота).
3. На экране бота введи почту и пароль аккаунта, поставь **«Оставаться в системе»**,
   пройди reCAPTCHA если появится.
4. Дойди до личного кабинета Zoom → в панели нажми **«3. Я вошёл»**.

Сессия сохранится в профиль и переживёт перезапуск. Логинить второй слот — под
**другим** аккаунтом (два бота под одним = конфликт хоста).

**Запасной путь (cookie):** экспортировать cookie zoom.us (расширение Cookie-Editor →
Export JSON) поверх `E:\myvibedev\zoom-cookies.json` (для слота 1 — `zoom-cookies-2.json`).
Бот подхватит файл сам при следующем заходе.

## 4. Заход в конференцию

- **В бою:** создай событие в блоке «Новое мероприятие» со ссылкой на конференцию —
  бот зайдёт по ней (сразу или по расписанию).
- **Для тестов:** бот может сам начать свою личную конференцию — это делает
  `POST /session/start` (кнопка/скрипт); в бою так не нужно, заходим по реальным ссылкам.

Если бот попал в зал ожидания — впусти его как организатор.

## 5. Видео и музыка (блок «Медиа бота»)

- **Видео** (.mp4/.webm, до 100 МБ) → идёт **в камеру** бота (участники видят ролик
  вместо заставки, со звуком).
- **Музыка** (.mp3/.ogg/.wav/.flac) → **только в микрофон**, на камере остаётся заставка.
- Загрузи файл, нажми ▶. mp4 и m4a бот сам перегоняет в WebM/Ogg (занимает время —
  в списке «перегон…»). .webm и .mp3 играют сразу.
- Играет один файл за раз.

## 6. Модерация чата

Работает автоматически, когда бот — организатор:
- **Мат** — удаляет + предупреждение в чат.
- **Спам** (повторы/флуд) — удаляет лишнее, оставляя последнее.
- Удаление идёт по одному за такт (пара секунд) — так надёжнее.

## 7. Зал ожидания (впуск по списку)

Блок **«Зал ожидания»**:
- Тумблер **«Авто-впуск по списку»**.
- Добавь разрешённые фамилии/имена. Совпало любое слово имени участника — впускает.
- Нет в списке — оставляет в зале (впускаешь вручную кнопкой ✓).
- Одно слово без фамилии — впускает и просит фамилию в чате.
- **Матерный ник** — не впускает.

## 8. Реакции и приветствия (блок «Реакции и приветствия»)

- Кнопки-эмодзи (👏 👍 ❤️ 😂 🎉 👋) — бот отправляет реакцию в конференцию.
- Тумблер **«Здороваться в ответ»** — бот отвечает на приветствие в чате (с кулдауном)
  и машет реакцией.

## 9. Мониторинг (блок «Живой просмотр»)

- **«Смотреть»** — живой экран бота (через noVNC, без звука). При смене вкладки
  показывает бота нужного слота. «↗ В отдельном окне» — крупно.
- **VU «Звук бота»** — полоска: видно, что бот отдаёт звук (музыка/ролик).
- **VU «Участники»** + **«Слушать участников»** — по кнопке слышно других участников
  в панели (звук конференции), полоска показывает их уровень.
- Экран бота — 16:9, во весь экран, без адресной строки; лишние уведомления Zoom
  бот закрывает сам; своё видео не зеркалит (текст читаем).

## 10. Ограничения

- **Free-аккаунт Zoom = лимит 40 минут** на конференцию: если бот — хост, митинг сам
  завершится через 40 мин, нужен перезаход. Для долгих — платный аккаунт.
- Cookie-сессия живёт ~сутки; долгий вход через noVNC («Оставаться в системе») держится
  дольше. При «сессия истекла» — повторить вход (п. 3).
- Два бота параллельно с камерой+звуком — примерно 1–2 ядра CPU, запас есть.

## 11. Если что-то не так

- **Пусто/старое в панели** — жёсткий перезагруз страницы (Ctrl+Shift+R): подхватит
  свежие скрипты/стили.
- **Бот замьючен / не слышно музыку** — бот включает мик сам при входе; если нет —
  перезайти.
- **После перезапуска Docker в контейнере лёг DNS** — `docker compose restart bot-browser`.
- **Экран/настройки не открываются** — экран 720p; координаты тулбара под него; при
  проблемах перезапустить бота.
