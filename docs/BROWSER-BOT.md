# Браузерный бот-модератор (bot-browser) — статус и что дальше

Составлено 13 июля 2026. Сервис `bot-browser` (порт 9100) — Zoom web-клиент
через Playwright (headful Chromium под Xvfb в Docker). Заменил хрупкий
desktop-путь (OCR + клики по пикселям) на управление через DOM.

---

## 1. Что уже работает (проверено вживую)

- **Модерация чата** — читает чат из DOM, опрос раз в 1 сек.
  - **Удаление мата** — стабильно (6+ подряд без осечек).
  - **Удаление спама** — флуд (6+ сообщений за 10с), повторы (3 одинаковых),
    короткие сообщения ≤3 символов — спам уже при 2 повторах. Повторы
    вычищаются с оставлением последнего.
  - **Предупреждения в чат с именем нарушителя**:
    - за мат: «⚠️ {имя}, веди себя прилично!»
    - за спам: «⚠️ {имя}, предупреждение за спам. Повторится — бан.»
    - одно предупреждение на автора раз в 60 сек (без самофлуда).
- **Виртуальная камера** — заставка «Тех. поддержка» (fake-video Chromium).
- **Виртуальный микрофон** — тестовый тон (fake-audio Chromium).
- **Локальная запись** — ffmpeg пишет экран бота (start/pause/resume/stop, mp4).

Всё в ветке `feature/virtual-mic-music`. Desktop-воркеры (bot-worker) не тронуты,
лежат в стопе как фолбэк.

---

## 2. Как запускать и тестировать

```bash
# поднять сервис
docker compose up -d bot-browser

# завести бота в митинг
curl -s -X POST http://localhost:9100/session/join \
  -H 'Content-Type: application/json' \
  -d '{"join_url":"https://us06web.zoom.us/j/<ID>"}'

# статус / события модерации / скриншот экрана бота
curl -s http://localhost:9100/session/status
curl -s http://localhost:9100/moderation/status
curl -s http://localhost:9100/screenshot -o shot.png

# запись экрана
curl -s -X POST http://localhost:9100/recording/start -d '{"target":"local"}'
curl -s -X POST http://localhost:9100/recording/stop  -d '{"target":"local"}'
curl -s http://localhost:9100/recordings

# вывести бота
curl -s -X POST http://localhost:9100/session/leave

# логи
docker logs -f myvibedev-bot-browser-1
```

**После входа боту нужно:** впустить из зала ожидания + выдать co-host/host
(иначе Zoom не даёт удалять чужие сообщения и мьютить).

## 3. Как лучше работать (рекомендации — экономят время)

1. **Отключить зал ожидания** для тестовой конференции (Security → снять
   «Зал ожидания»). Тогда бот заходит сам, не нужно впускать при каждом
   перезаходе — главный ускоритель итераций.
2. **Правки кода требуют перезапуска контейнера** (`--reload` убран нарочно —
   он ронял live-сессию браузера). После правок:
   `docker compose up -d --force-recreate bot-browser`, затем заново `join`.
   ВНИМАНИЕ: перезаход сбрасывает роль — co-host/host выдавать заново.
   Именно поэтому в планах «бот сам стартует конференцию» (тогда он сразу хост).
3. **Диагностика — по логам.** В коде подробные логи: `delete … удалено/НЕ
   удалилось`, `прочитано N новых, авторы: […]`, `в меню: […]` при неудаче
   удаления, `mute: строк в панели …`. Сначала смотреть логи, не гадать.
4. **Тест-сценарий:** мат → удаление + «веди себя прилично»; три одинаковых
   коротких («ааа»×3) → удаление до последнего + «за спам… бан».

## 4. Что дальше (по приоритету)

### A. Мьют нарушителя (код готов — нужен живой тест)
Включён (`MUTE_ENABLED=True`). Что сделано:
- кнопка мьюта ищется по aria-label **и видимому тексту** («Mute»/«Выключить
  звук»); «Unmute»/«Включить звук» = уже замьючен, считается успехом;
- фолбэк через меню «Ещё»/«More» строки участника;
- при неудаче в лог пишутся **все подписи кнопок строки** и пункты меню —
  по ним выверить селектор с первого теста (как делали с удалением);
- мьют под тем же кулдауном (60с), что предупреждение — при флуде панель
  участников не дёргается на каждое сообщение;
- панель чата возвращается всегда (`ensure_chat_open` в finally).

**Живой тест:** флуд с шумом в микрофон → в логах `mute: клик по кнопке…`
или `mute: подписи кнопок строки: […]` — по ним доводить.

### B. Веб-интерфейс под браузерного бота (крупный блок)
- **Два мероприятия параллельно** (как было 2 bot-worker на desktop).
- **Загрузка видео из веб-интерфейса до 100 МБ** — заставка/контент для камеры.
  Пользователь даст видео. Проверить/протестить.
- **Плеер видео+звук**: общий на оба мероприятия ИЛИ два отдельных, если
  ресурсов немного и не станет слабым местом.

### C. Автономность входа (снимает ручную возню)
- **Бот сам начинает конференцию** — тогда он изначально хост, впуск и co-host
  не нужны. Нужен вход в аккаунт бота в браузере → New Meeting.
- **Вход по коду организатора (host key / Claim Host)** — разведать, есть ли
  в web-клиенте.

### D. Мелочи
- Камера мигает — fake-video (.y4m) не зацикливается стабильно, нужен
  бесконечный луп.
- Микрофон — заменить тестовый тон на музыкальный плейлист (PulseAudio + mpv),
  проверить, не режет ли Zoom web музыку без «Original sound».
- Аудио в записи — сейчас `default` PulseAudio, связать со звуком митинга.
- ~~Баг детекта: код считает ЗАЛ ОЖИДАНИЯ за вход~~ — исправлено: зал
  ожидания определяется по тексту страницы, статус `waiting`; после впуска
  бот сам доводит вход (аудио/камера/чат — `complete_join`).

## 5. Ключевые уроки (чтобы не наступать снова)

- **DOM надёжнее пикселей.** Синтетические события (`dispatchEvent`) Zoom
  игнорирует — hover и клики только через настоящий Playwright (`el.hover()`,
  `el.click()`).
- **Права решают.** Без co-host/host у сообщений нет пункта «Удалить», у
  участников нет мьюта — всё уходит в `flagged`.
- **UI зависит от роли:** у полного хоста пункт меню называется «Удалить для
  всех», не «Удалить» — искать по подстроке.
- **Панель чата ≠ всплывашка.** Класс сообщения носит и toast-превью при
  закрытой панели — «открытость» проверять по видимому полю ввода.
