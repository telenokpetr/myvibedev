# Ретро и план — браузерный бот-модератор Zoom (15 июля 2026)

Итог большой сессии по `bot-browser`: разбор что сделали, что ломалось и чему
научились, текущее рабочее состояние и приоритетный план дальше.

---

## 1. С чего начинали и куда пришли

**Стартовая цель:** доделать **мьют** нарушителя (он не работал).
**По ходу вскрылось:** чтобы мьютить, бот должен быть хостом/со-хостом, а Zoom
блокировал автозаход бота антибот-защитой. Это увело в большую ветку —
**авторизация бота под Zoom-аккаунтом**. В итоге:

- ✅ **Вход бота под аккаунтом** — работает (через импорт cookie).
- ✅ **Авторизованный заход = сразу хост** — URL уходит на `/wc/<id>/start`.
- ✅ **Модерация** (чтение чата, удаление мата, предупреждения) — работает надёжно.
- ⏳ **Мьют** — отложен (осталось доковырять селектор панели участников).

## 2. Что ломалось и чему научились (ретро)

### Zoom против автоматизации
- **Заход ботом** без авторизации → «Боты не могут присоединяться» (появляется
  после нескольких быстрых перезаходов с одного IP/отпечатка).
- **Автовход через форму** Zoom **невозможен**: email-first форма проходится, но
  на финальном submit — «Произошла ошибка ввода reCAPTCHA». reCAPTCHA v3
  (невидимая, по поведению) даёт ботовому браузеру низкий балл. Ни антидетект
  (постоянный профиль, User-Agent, скрытие `navigator.webdriver`), ни
  человеко-подобная мышь + ретраи это не обошли.
- **Решение — импорт cookie:** человек логинится сам (reCAPTCHA проходит), cookie
  переносятся в профиль бота. Работает, т.к. бот и браузер выходят через один IP.
  Реализовано: `POST /account/import-cookies` → читает `/data/zoom-cookies.json`.

### Мои собственные баги (важный урок — не ломать соседнее)
- **`debug_hold`**: добавил флаг для разведки панели участников, он остался
  включённым и **молча остановил всю модерацию** (чтение+удаление). Убрал из
  гейта `_poll`. Урок: не оставлять debug-переключатели в горячем пути.
- **Чат не открывался**: `_open_chat` не находил кнопку, т.к. **тулбар Zoom
  прячется при простое** (в Xvfb мышь не двигается). Добавил `_reveal_toolbar()`
  (движение мыши) перед открытием. Тот же корень мешал и мьюту.

### Хрупкости веб-автоматизации
- **Ховер под Xvfb** иногда не поднимает кнопку «...» с первого раза → часть
  удалений флейкала. Лечение: 3 попытки ховера со сбросом мыши + **ретрай
  неудачного удаления** (сообщение перечитывается, кулдаун 12с, до 3 раз).
- **Селекторы по тексту**: искали по тексту всего контейнера — у первого
  сообщения в группе автора в контейнер попадает шапка «Имя Кому Все время», и
  точное совпадение ломалось (напр. «пидарас» не удалялся). Теперь ищем по
  тексту сообщения (`text-content`) внутри строки.
- **Счётчик сообщений** считал по всем вложенным узлам (`[class*=new-chat-message]`)
  → завышал в разы. Теперь по контейнерам строк.

### Операционные грабли
- **Cookie-сессия Zoom протухает ~за сутки** → бот снова заходит анонимом и
  ловит блок. Надо освежать файл `zoom-cookies.json` (или дать боту свой аккаунт
  и ставить «оставаться в системе» для долгой сессии).
- **Один аккаунт на бота и человека = конфликт хоста**: если человек хостит тем
  же аккаунтом, что и бот, Zoom завершает конференцию. Для теста мьюта человек
  должен заходить **гостем с другим именем**.
- **Аварийная остановка Docker Desktop** побила профиль (куки не дозаписались) —
  после чистого `docker compose restart` профиль переживает нормально.

## 3. Текущее рабочее состояние

- **Вход:** cookie-импорт → бот заходит как аккаунт-организатор, сразу хост.
- **Модерация:** читает чат, удаляет мат (расширенный словарь; анатомические типа
  «пенис» — НЕ мат), шлёт предупреждение «⚠️ Имя, не ругайся пёс!», удаляет спам
  (повторы/флуд/короткие), неудачные удаления ретраятся.
- **Веб-панель «Аккаунт бота»** подключена к `bot-browser:9100`.
- **Камера/микрофон/запись** — как раньше (заставка, fake-media, ffmpeg).

Запуск/тест — см. [BROWSER-BOT.md](BROWSER-BOT.md). Ключевое:
`POST /account/import-cookies` (после `docker cp zoom-cookies.json …:/data/`),
затем `POST /session/join`.

## 3-bis. МЬЮТ — решён (15.07, вечер)

**Панель участников — тупик.** Клик по верной кнопке («open the manage
participants list pane, N particpants») переводит контейнер в
`wc-container-left.show-participants`, но **ростер в DOM не появляется** (там
шапка/логотип/тост). Перепробованы все классы — списка нет. Не тратить время.

**Рабочий путь — ВИДЕО-ПЛИТКА участника** (`_mute_via_tile` в `zoomweb.py`):
1. Найти плитку: `[class*="video-avatar__avatar"]` с текстом-именем (или
   `:has(img[alt="Имя"])`).
2. РЕАЛЬНЫЙ `hover` по плитке → всплывают кнопки.
3. Разведанные подписи Zoom (проверены вживую):
   - `Выключить звук` → жать (это и есть мьют);
   - `Попросить включить звук` → участник **уже замьючен** (успех, не жать —
     иначе размьютим);
   - `More managing options` → меню «...» плитки.
4. Меню «...» у ХОСТА содержит: Чат, Переименовать, Добавить закрепление,
   **Удалить**, **Перевести в зал ожидания**, Отчет. У обычного участника —
   только Чат/Закрепить/Отчет (мьюта нет).

**ПРАВА РЕШАЮТ (важно):**
- **Со-организатор НЕ может** удалять сообщения и мьютить **ХОСТА** — у таких
  сообщений даже не всплывает «...» (лог: `delete: «...» не поднялась (3 попытки)`).
  При этом сообщения обычных участников со-хост удаляет нормально.
- Боту нужен **ОРГАНИЗАТОР** (или нарушитель должен быть обычным участником).
- Проверено: при host-правах `hostTools:true` + кнопка «Завершить».

**Что НЕ доверено вживую:** сам клик «Выключить звук» — цель (Ekaterina) всё
время была замьючена, кнопка не появлялась. Всё до клика работает; регэкспы
`_RX_MUTE`/`_RX_UNMUTE` проверены на реальных подписях. Осталось увидеть мьют
на РАЗмьюченном участнике.

**Заход (разведано):** чистая `/j/`-ссылка работает (конвертится в
`app.zoom.us/wc/join/<id>`). Host-ссылка `/wc/<id>/start?omn=...&ref_from=launch&fromPWA=1`
даёт prejoin, где кнопка «Войти» не ловится — бот молча виснет. В `join()` добавлен
ретрай клика «Войти» (3 попытки с ожиданием видимости).

**Мои баги, которые ломали соседнее (исправлены):**
- `debug_hold` в `_poll` молча останавливал чтение+удаление → убран.
- Ретрай неудачного удаления (`_seen.discard`) **зацикливал** цикл на
  неудаляемых сообщениях и вешал браузер («прочитано N новых» каждую секунду) →
  убран. Флейки ховера гасит `_open_message_menu` (3 попытки внутри).

## 4. План — что дальше (по приоритету)

### P1. Мьют — финальная проверка
- `MUTE_ENABLED=True`, `_mute_via_tile` задеплоен. Осталось проверить на
  **размьюченном** участнике: бот должен нажать «Выключить звук».
- Тест-харнес: `POST /debug/mute {"name":"..."}` — мьютит по имени без ожидания
  мата. Плюс `POST /debug/pause {"seconds":N}` — пауза цикла с авто-снятием
  (для разведки), `POST /debug/eval {"js":"..."}` — JS на живой странице.
- Условия теста: бот = **организатор**, цель = участник с **другим именем**, у
  цели **включён микрофон**.

### P2. Два вебинара параллельно
- Второй экземпляр `bot-browser-2` (свой профиль/порт). Веб уже маршрутизирует по
  `slot` (`bot_worker_urls`, `_worker(slot)`), фронт умеет слоты.
- Каждому слоту — свой аккаунт/cookie (иначе конфликт хоста).

### P3. Вход по host key / коду доступа
- Разведать, поддерживает ли web-клиент host key (Claim Host) и ввод кода
  доступа при заходе. Добавить опцию в join (поле passcode уже летит в payload,
  но bot-browser его пока игнорирует).

### P4. Надёжность авторизации
- Cookie протухают: либо периодически освежать файл, либо дать боту **отдельный
  аккаунт** с длинной сессией. Рассмотреть авто-подхват cookie из файла при
  каждом join (не зависеть от профиля).

### P5. Полировка модерации
- Добить редкий флейк удаления коротких сообщений при быстром флуде.
- Донастроить словарь и правила спама по фидбеку.

## 5. Ключевые файлы

- `bot-browser/app/zoomweb.py` — драйвер Zoom web (вход, чат, удаление, cookie,
  логин-форма, мьют, debug-дампы).
- `bot-browser/app/moderator.py` — цикл модерации, ретраи, предупреждения, мьют.
- `bot-browser/app/account.py` — менеджер входа в аккаунт (форма + импорт cookie).
- `bot-browser/app/moderation.py` — словарь мата, классификация, спам.
- `bot-browser/app/main.py` — REST API (`/session/*`, `/account/*`, `/debug/*`).
- `web/app/` — веб-панель (аккаунт, слоты, модерация), маршрут на `bot-browser`.
