# Калибровка bot-worker на живом Zoom (проверено вживую)

Здесь зафиксированы реальные шаги/координаты/настройки, отработанные на живом
клиенте **Zoom Workplace 7.1.0 (Linux, Xvfb 1280×720)**. Это фактическая карта
для превращения заглушек в `bot-worker/app/gui.py` в рабочую автоматизацию.

> Все координаты — для разрешения `SCREEN_GEOMETRY=1280x720x24`. При смене
> геометрии их надо пересчитать. Клиент рендерится под Xvfb штатно.

## 1. Вход в конференцию по ссылке

`zoommtg://`-ссылка (см. `zoom.py`) реально открывает митинг. Дальше — стадии:

| Стадия | Экран | Действие |
|--------|-------|----------|
| Пред-вход | превью «Модератор», кнопки **Join / Sign in** | клик **Join** (в развёрнутом окне ≈ `1045,32` вверху — это Sign in; кнопка Join — правый-низ диалога) |
| Ожидание | «Waiting for host to start the meeting» | ждать |
| Waiting Room | «Host has joined. We've let them know you're here» | **admit делает только хост**; бот сам себя впустить не может |
| Аудио | «Choose one of the audio conference options» | клик **Join with Computer Audio** ≈ `637,323` |
| Мик не найден | «Zoom cannot detect your microphone» | безобидно (решается через BotMic, см. §5) |
| В митинге | тулбар с Participants/Chat/More | работать |

**Важно:** штатные 2×Enter (`dismiss_startup_dialogs`) экран пред-входа НЕ
проматывают — нужен явный клик по **Join**.

## 2. Права хоста — САМЫЙ надёжный путь

`claim_host(host_key)` через UI **не работает, пока в митинге есть активный
хост** (пункта «Claim Host» в меню просто нет). Рабочая схема, проверенная вживую:

1. Бот входит в Zoom **под аккаунтом-владельцем конференции** (см. §3).
2. Когда организатор выходит — **хост автоматически переходит боту**
   (уведомление «You are the host now»). host key при этом НЕ нужен.

То есть для автономной модерации/записи бот должен быть залогинен под
owner-аккаунтом, а не забирать хост ключом.

## 3. Вход в аккаунт Zoom (десктоп)

Последовательность (капчи не было, но есть OTP):

1. Тулбар/окно → **Sign in** (≈ `1045,32`).
2. Поле email ≈ `498,324` → ввести → **Next** ≈ `498,380`.
3. Поле пароля ≈ `498,351`, «Stay signed in» ≈ `326,401` → **Sign in** ≈ `498,456`.
4. **One-time Passcode**: Zoom шлёт 6-значный код НА ПОЧТУ аккаунта. Ввести в
   первое поле ≈ `348,247` (авто-submit после 6 цифр).

⚠️ OTP приходит на email → **полностью headless вход невозможен** без доступа к
почте. «Stay signed in» сохраняет сессию между запусками, НО профиль Zoom лежит в
`$HOME` контейнера (не в volume) — при пересоздании контейнера логин теряется.
Аккаунт был **Free** → облачная запись Zoom недоступна, только локальный ffmpeg.

## 4. Модерация как хост

- **Rename участника:** Participants → «…» у участника → **Rename** → OK.
  Кириллицу через `xdotool type` вводить ненадёжно — надёжнее дописывать латиницу
  к уже существующему тексту поля.
- **Mute All:** Participants → **Mute All** (низ панели ≈ `1060,686`) → в диалоге
  **Mute All** ≈ `744,421`. Снять галку «Allow participants to unmute themselves»
  ≈ `399,421` для жёсткого мьюта.

## 5. Аудио-топология (запись + виртуальный микрофон)

```
vspeaker (null-sink)  ← Zoom SPEAKER (звук митинга)   → vspeaker.monitor: запись, превью, VAD
vmic     (null-sink)  ← music_daemon (ffmpeg)          → vmic.monitor
                                                        → BotMic (remap-source) = МИКРОФОН Zoom
```

Ключевые фиксы (без них не работает):

1. **Микрофон бота = BotMic.** Голый `vmic.monitor` Zoom НЕ показывает как
   микрофон. Нужен `module-remap-source master=vmic.monitor source_name=BotMic`
   (добавлено в `entrypoint.sh`). Тогда в Zoom Audio settings → Microphone
   появляется «BotMic», его надо выбрать.
2. **Запись без звука → поднять Output volume.** Громкость вывода Zoom по
   умолчанию стояла ~0 → в null-sink уходила тишина → немая запись. Выставить
   **Output volume = 100%** (Audio settings, ползунок вправо ≈ `1205,343`).
3. **Музыку глушил шумодав.** «Microphone modes: Noise removal» вырезает музыку
   как шум. Включить **«Original sound for musicians»** (Audio-меню, пункт
   ≈ `173,548`) — отключает шумоподавление, музыка проходит.

## 6. Виртуальный микрофон с музыкой — `bot-worker/music_daemon.py`

Фоновый демон:
- играет треки из `/data/music` по очереди (чередование), зациклено;
- **автопауза по голосу**: речь непрерывно > 2 c → пауза (SIGSTOP ffmpeg);
  тишина непрерывно ≥ 60 c → возобновление (SIGCONT);
- детектор голоса (VAD) слушает `vspeaker.monitor` (речь других участников),
  музыка идёт в `vmic` — не пересекаются, музыка сама себя не триггерит.

Параметры через env (все настраиваются на лету перезапуском демона):

| env | дефолт | смысл |
|-----|--------|-------|
| `MUSIC_VOL` | 0.4 | громкость музыки (фильтр `volume=`); меньше = тише |
| `SPEECH_RMS` | 150 | порог детекции речи (RMS s16); **меньше = чувствительнее** |
| `SPEAK_PAUSE` | 2.0 | сек непрерывной речи до паузы |
| `SILENCE_RESUME` | 60 | сек непрерывной тишины до возобновления |

Пол тишины на `vspeaker.monitor` при молчании = **0** (цифровая тишина null-sink),
поэтому порог можно держать низким без ложных срабатываний.

Проверено вживую: `PAUSE — речь 2.0s` → `RESUME — тишина 60s`. Треки Вагнера
(public domain, archive.org) кладутся в `/data/music`.

Запуск: `MUSIC_VOL=0.2 SPEECH_RMS=150 python3 /app/music_daemon.py`.
Стоп: `pkill -f music_daemon`.

## 7. Найденные баги (ещё не исправлены)

- **Английский мат не детектится** (`moderation.py`): таблица `_LEET` мапит
  латинские буквы в кириллицу (`c→с`, `x→х`…) и портит англ. корни до сравнения
  (`fuck`→`fuс​k`). Из англ. списка выживает только `shit`. Фикс: проверять
  regex и по «сырому», и по нормализованному тексту.
- **«Слепой» state machine** (`session.py`): статус `live` ставится после
  фиксированного `sleep(8)` без проверки, что вход удался (при «Invalid meeting
  ID» статус тоже был `live`). Нужна верификация по окну/скриншоту.
- **Зомби-процесс zoom** после `leave`: `zoom.kill()` шлёт `pkill`, но не делает
  `wait()` на Popen → копится по одному `[zoom] <defunct>` за сессию.
