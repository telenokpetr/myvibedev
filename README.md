# Zoom Bot Console

Сервис для автоматизации лекций/вебинаров в Zoom: бот на базе Ubuntu-VM входит в
конференцию по расписанию, при необходимости запускает запись, ведёт простую
модерацию чата (спам, нецензурные слова) и отдаёт живой просмотр происходящего
(скриншоты экрана) в веб-интерфейс.

> **Статус:** этап 1 из 7 — базовый каркас. Дорожная карта ниже.

## Как это работает

1. В веб-интерфейсе создаётся **мероприятие**: вставляется **ссылка** на уже
   существующую конференцию, код доступа (если нужен) и **код организатора
   (host key)**.
2. Режим запуска — **«сейчас»** или **«по расписанию»** (бот сам зайдёт в заданное
   время).
3. **Bot-worker** (Ubuntu + Xvfb + десктоп-клиент Zoom) заходит по ссылке под
   **своим тех-аккаунтом**, вводит host key и через «Claim Host» становится
   **организатором/со-организатором**.
4. При включённой опции — стартует **запись** (захват экрана через `ffmpeg`).
5. **Модерация чата** (спам/нецензурщина) — слой `ChatReader` (AT-SPI → OCR).
6. В веб-интерфейсе видно **живой скриншот** происходящего и события модерации.

## Архитектура

```
web (FastAPI)   — веб-интерфейс, мероприятия, REST/WS, живой просмотр
scheduler       — по времени даёт bot-worker команду войти и включить запись
bot-worker      — Ubuntu + Xvfb + Zoom-клиент: вход по ссылке, claim host,
                  запись, скриншоты, чтение/модерация чата
db (Postgres)   — мероприятия, логи, события модерации
redis           — брокер задач планировщика
```

> **Zoom REST API не используется:** мы не создаём митинги, а присоединяемся по
> готовой ссылке и забираем роль хоста по host key через десктоп-клиент. Запись —
> локально через `ffmpeg`, поэтому платный аккаунт с облачной записью не обязателен.

## Быстрый старт

```bash
cp .env.example .env       # заполнить пароли/секреты
docker compose up --build
```

- Веб-интерфейс: <http://localhost:8000>
- Health: <http://localhost:8000/health>

## Тесты

Юнит-тесты обоих сервисов работают офлайн (без Docker/Xvfb/Postgres):

```bash
# bot-worker: движок модерации + разбор Zoom-ссылок
cd bot-worker && pip install -r requirements-dev.txt && pytest

# web: CRUD мероприятий на SQLite in-memory
cd web && pip install -r requirements-dev.txt && pytest
```

CI (GitHub Actions, `.github/workflows/ci.yml`) гоняет оба набора на каждый push/PR.

## Требования

- Docker + Docker Compose
- Zoom-аккаунт с доступом к <https://marketplace.zoom.us> (для этапа 3)
- Отдельный тех-аккаунт Zoom для бота (для этапа 5)

## Замечания по правилам

Запись и модерация требуют, чтобы бот был host/co-host, а участников необходимо
уведомлять о записи (Zoom обычно показывает баннер автоматически). Использовать
только на своих мероприятиях и в рамках Zoom Terms of Service.
